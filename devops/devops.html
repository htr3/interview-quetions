What is CI/CD?

Easy⭐ VIBasics▼

Quick answer

CI = merge code frequently, automated build+test on each commit. CD = automated deploy to staging/prod with approvals and rollback.

From your experience

Optima Jenkins: Maven build → TestNG → artifact to Nexus → deploy stages per env — ~60% less manual deploy effort.

Follow-ups

Continuous deployment vs delivery? Deployment = auto to prod; delivery = auto to staging, manual prod gate.

STAR: Jenkins pipelines — 60% manual effort reduction

Hard⭐ VIJenkins▼

Quick answer

Replaced manual JAR copy/config/restart with standardized pipeline — consistent releases, faster feedback, team freed for features.

Detailed explanation

  • Declarative or scripted pipeline with stages: checkout, build, test, publish, deploy
  • Credentials for SSH/deploy; parameterized env (dev/test/prod)
  • Notifications on failure; smoke test post-deploy (health URL)
  • SM Tool complemented Jenkins for Fuse-specific deploy steps

Example

pipeline {
  stages {
    stage('Build') { steps { sh 'mvn -B clean package' } }
    stage('Test') { steps { sh 'mvn test' } }
    stage('Deploy') { steps { /* promote artifact */ } }
  }
}

Follow-ups

How rollback? Redeploy previous artifact tag from Nexus; blue-green if infra supports.

Docker basics for Java microservices

MediumDocker▼

Quick answer

Image = app + JRE layers; container = running instance. Multi-stage build: Maven in builder, slim JRE runtime image.

Example

FROM eclipse-temurin:17-jre
COPY target/app.jar /app.jar
ENTRYPOINT ["java","-jar","/app.jar"]

Follow-ups

Don't run as root; set memory limits; healthcheck in Dockerfile or K8s probe.

CI vs CD — explain in your own Jenkins pipeline

Easy⭐ VICI/CD▼

CI: every merge runs build + tests automatically. CD: artifact is always deployable; pipeline promotes to staging/prod with checks. Your Optima work: CI catches bad code early; CD removed ~60% manual deploy steps.

Container vs virtual machine — simple comparison

MediumDocker▼

VM runs full OS per instance — heavy. Container shares host kernel — lighter, starts in seconds. Both package apps; containers pack more per server. K8s orchestrates containers at scale.
