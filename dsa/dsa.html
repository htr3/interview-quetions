1. Basic Concepts

Time & space complexity (Big O), recursion & backtracking, mathematical basics (GCD, primes).

6 questions in this section

Big O — explain time and space with examples

Easy⭐ VIBasics▶ Visual▼

Quick answer

Describes growth rate as input grows — worst-case upper bound. O(1) constant, O(log n) halving, O(n) single pass, O(n log n) efficient sort, O(n²) nested loops on n.

Examples

// O(n) — single loop
for (int x : arr) sum += x;

// O(n²) — nested loops on same n
for (int i = 0; i < n; i++)
  for (int j = i + 1; j < n; j++) ...

Space complexity

Extra memory beyond input — e.g. HashMap of size n → O(n) auxiliary space; in-place swap → O(1).

Follow-ups

Amortized O(1) ArrayList append — occasional resize copies all elements.

Time complexity order to memorize

Medium⭐ VIBasics▶ Visual▼

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ). Always state both time and space after every solution.

Common operations

  • Binary search: O(log n)
  • HashMap get/put: O(1) average
  • Merge sort / heap sort: O(n log n)
  • BFS/DFS on graph: O(V + E)

Recursion vs backtracking — when to use each?

Medium⭐ VIBasics▶ Visual▼

Recursion

Function calls itself on smaller subproblem — tree height, factorial, merge sort divide step. Needs base case + progress toward base case.

Backtracking

Try choice → recurse → undo choice if path fails. Used for subsets, permutations, N-Queens, maze paths.

Template

void backtrack(int idx, List<Integer> path) {
  if (idx == nums.length) { result.add(new ArrayList<>(path)); return; }
  path.add(nums[idx]);
  backtrack(idx + 1, path);
  path.remove(path.size() - 1); // undo
  backtrack(idx + 1, path);    // skip
}

Complexity

Often exponential — prune early (sort + skip duplicates, bounds check).

GCD and prime numbers — interview math basics

EasyMath▶ Visual▼

GCD (Euclidean algorithm)

int gcd(int a, int b) {
  while (b != 0) { int t = b; b = a % b; a = t; }
  return a;
}

O(log min(a,b)). LCM(a,b) = a*b / gcd(a,b).

Prime check

Test divisors up to √n — O(√n). Sieve of Eratosthenes for many primes up to N — O(N log log N).

Where it appears

Modular arithmetic, coprime pairs, scheduling problems, cryptography basics.

How to approach any DSA problem in interviews

  2. Walk through a small example on whiteboard
  3. Brute force → optimize; pattern match: sliding window, two pointers, BFS/DFS, DP, heap
  4. Code cleanly in Java; extract helpers
  5. Test edge case verbally; state time & space complexity

Mention Amdocs India Coding Champion — structured thinking under time pressure.

Space complexity — common examples

EasyBasics▶ Visual▼
  • O(1): two pointers, iterative reverse list, swap in array
  • O(n): HashMap for Two Sum, recursion stack depth n, BFS queue
  • O(n²): DP table n×n, adjacency matrix

Recursion depth = tree height — skewed tree O(n), balanced O(log n).

2. Arrays & Strings

Traversal, sliding window, prefix sum, two pointers, string manipulation & pattern matching.

Two Sum — HashMap approach

Easy⭐ VIArray▶ Visual▼

Quick answer

Store value→index; for each x check if (target − x) seen. O(n) time, O(n) space.

public int[] twoSum(int[] nums, int target) {
  Map<Integer, Integer> seen = new HashMap<>();
  for (int i = 0; i < nums.length; i++) {
    int need = target - nums[i];
    if (seen.containsKey(need)) return new int[] { seen.get(need), i };
    seen.put(nums[i], i);
  }
  return new int[0];
}

Follow-up

Sorted array → two pointers O(n) O(1) space.

Sliding window — longest substring without repeating characters

Medium⭐ VIArray▶ Visual▼

Pattern

Expand right, shrink left when constraint breaks. Fixed window = subarray sum exactly K; variable window = longest/shortest satisfying condition.

int left = 0, best = 0;
Map<Character, Integer> last = new HashMap<>();
for (int right = 0; right < s.length(); right++) {
  char c = s.charAt(right);
  if (last.containsKey(c)) left = Math.max(left, last.get(c) + 1);
  last.put(c, right);
  best = Math.max(best, right - left + 1);
}

O(n) time, O(1) space (charset size bounded).

Prefix sum — range sum queries & subarray sum equals K

Medium⭐ VIArray▶ Visual▼

Prefix array

prefix[i] = sum(nums[0..i]). Range sum [l,r] = prefix[r] − prefix[l−1] in O(1) after O(n) preprocess.

Count subarrays with sum K

Running prefix + HashMap count of prefix values seen. If (currSum − K) exists in map, add its frequency.

Map<Long, Integer> freq = new HashMap<>();
freq.put(0L, 1);
long sum = 0, count = 0;
for (int x : nums) {
  sum += x;
  count += freq.getOrDefault(sum - K, 0);
  freq.merge(sum, 1, Integer::sum);
}

O(n) time, O(n) space.

Two-pointer technique — container with most water

Medium⭐ VIArray▶ Visual▼

Idea

Start left=0, right=n−1. Area = min(height[l], height[r]) × (r−l). Move the shorter line inward — only that move can increase area.

Also used: sorted array pair sum, remove duplicates in-place, merge two sorted arrays.

O(n) time, O(1) space.

Valid Anagram — string manipulation

EasyString▶ Visual▼

Count char frequencies — equal counts iff anagram. O(n) time, O(1) space (26 letters).

int[] count = new int[26];
for (char c : s.toCharArray()) count[c - 'a']++;
for (char c : t.toCharArray()) if (--count[c - 'a'] < 0) return false;
return true;

Pattern matching intro

KMP / Rabin-Karp for single-pattern search — mention if asked; HashMap + sliding window covers most interviews.

Array traversal, insertion, deletion — complexity

EasyArray▶ Visual▼
  • Access by index: O(1)
  • Search unsorted: O(n)
  • Insert/delete at end (ArrayList): amortized O(1)
  • Insert/delete at middle: O(n) — shift elements

3. Linked List

Singly, doubly, circular lists; reversal; Floyd's cycle detection.

4 questions in this section

Singly vs doubly vs circular linked list

EasyLinked List▶ Visual▼
  • Singly: one next pointer — less memory, can't traverse backward
  • Doubly: next + prev — O(1) delete at known node (LRU cache), bidirectional traversal
  • Circular: last node points to head — round-robin schedulers, Josephus problem

Java: LinkedList<E> is doubly-linked; no built-in singly-linked list — define ListNode { int val; ListNode next; }.

Reverse linked list (iterative)

Medium⭐ VILinked List▶ Visual▼

Three pointers: prev, curr, next. O(n) time, O(1) space.

public ListNode reverse(ListNode head) {
  ListNode prev = null, curr = head;
  while (curr != null) {
    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
  }
  return prev;
}

Follow-up

Reverse between positions m and n — find node before m, reverse sublist length (n−m+1).

Cycle detection — Floyd's tortoise and hare

Medium⭐ VILinked List▶ Visual▼

Has cycle?

Slow moves 1, fast moves 2. If they meet → cycle. O(n) time, O(1) space.

Find cycle start

After meeting, reset slow to head; move both 1 step until they meet — that node is cycle entry.

boolean hasCycle(ListNode head) {
  ListNode slow = head, fast = head;
  while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;
  }
  return false;
}

Merge two sorted linked lists

EasyLinked List▶ Visual▼

Dummy head + tail pointer; pick smaller node each step. O(n+m) time, O(1) space.

Extension: merge K sorted lists → min-heap of size K (see Heap section).

4. Stack & Queue

LIFO stack, FIFO queue, circular queue, deque; applications like balanced parentheses.

5 questions in this section

Real uses of stack and queue in backend systems

Easy⭐ VIStack▶ Visual▼

Stack (LIFO): undo operations, DFS, parsing nested XML/JSON, JVM call stack, expression evaluation.

Queue (FIFO): thread pools, message buffers, BFS, async job pipelines, Camel route pipelines.

Valid parentheses — stack application

Easy⭐ VIStack▶ Visual▼

Push opening brackets; on closing, pop must match. O(n) time, O(n) space.

Deque<Character> stack = new ArrayDeque<>();
for (char c : s.toCharArray()) {
  if (isOpen(c)) stack.push(c);
  else if (stack.isEmpty() || !matches(stack.pop(), c)) return false;
}
return stack.isEmpty();

Queue, circular queue, and deque

EasyQueue▶ Visual▼
  • Queue: offer/poll O(1) — ArrayDeque in Java (faster than synchronized Queue)
  • Circular queue: fixed-size buffer, front/rear wrap with modulo — bounded memory in embedded systems
  • Deque: double-ended — sliding window max (monotonic deque), palindrome check both ends

Min stack — O(1) getMin

MediumStack▶ Visual▼

Second stack tracks current minimum. On push(x): push min(x, peekMinStack). On pop: pop both. O(1) per operation.

Variant: evaluate RPN, daily temperatures (monotonic stack).

Implement queue using two stacks

MediumQueue▶ Visual▼

inStack for enqueue; on dequeue, if outStack empty pour inStack → outStack. Amortized O(1) per op.

Classic design interview — shows understanding of amortized analysis.

5. Trees

Binary tree, BST, traversals, height/depth/diameter, lowest common ancestor (LCA).

6 questions in this section

Tree traversals — inorder, preorder, postorder

Easy⭐ VITree▶ Visual▼
  • Inorder (L, root, R): BST → sorted order
  • Preorder (root, L, R): copy tree, prefix expression
  • Postorder (L, R, root): delete tree, postfix expression
void inorder(TreeNode node, List<Integer> out) {
  if (node == null) return;
  inorder(node.left, out);
  out.add(node.val);
  inorder(node.right, out);
}

Iterative inorder: stack + go left until null, pop, go right. O(n) time.

Level order traversal (BFS on tree)

Medium⭐ VITree▶ Visual▼

Queue + process size nodes each level. O(n) time, O(n) space worst (last level).

Queue<TreeNode> q = new LinkedList<>();
q.offer(root);
while (!q.isEmpty()) {
  int size = q.size();
  List<Integer> level = new ArrayList<>();
  for (int i = 0; i < size; i++) {
    TreeNode node = q.poll();
    level.add(node.val);
    if (node.left != null) q.offer(node.left);
    if (node.right != null) q.offer(node.right);
  }
  result.add(level);
}

Binary Search Tree (BST) — search, insert, validate

Medium⭐ VITree▶ Visual▼

Left < root < right at every node. Search/insert O(h) — O(log n) if balanced, O(n) if skewed.

Validate BST

Pass min/max bounds down recursion — not just compare parent.

boolean isValid(TreeNode node, long min, long max) {
  if (node == null) return true;
  if (node.val <= min || node.val >= max) return false;
  return isValid(node.left, min, node.val)
      && isValid(node.right, node.val, max);
}

Height, depth, and diameter of a binary tree

MediumTree▶ Visual▼
  • Height: max edges root to leaf — recursive max(left, right)+1
  • Depth of node: distance from root to that node
  • Diameter: longest path between any two nodes — at each node: leftHeight + rightHeight, track global max

Balanced tree check: |height(left) − height(right)| ≤ 1 at every node.

Lowest Common Ancestor (LCA)

Medium⭐ VITree▶ Visual▼

BST

Walk from root: if both < root go left; both > root go right; else root is LCA. O(h).

Binary tree

Postorder: if node is p or q return node; left/right recursive; if both non-null current is LCA else return non-null child.

Maximum depth of binary tree

EasyTree▶ Visual▼
int maxDepth(TreeNode root) {
  if (root == null) return 0;
  return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}

O(n) time. DFS recursion depth = tree height — watch stack overflow on skewed million-node tree (rare in interviews).

6. Heap (Priority Queue)

Min/max heap, heap operations, heap sort, top-K problems.

4 questions in this section

Min heap vs max heap — operations and Java API

Medium⭐ VIHeap▶ Visual▼

Complete binary tree: parent ≤ children (min-heap) or parent ≥ children (max-heap).

  • insert / poll: O(log n)
  • peek min/max: O(1)
  • build heap from array: O(n)
// Min-heap (default)
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
// Max-heap
PriorityQueue<Integer> maxHeap =
    new PriorityQueue<>(Collections.reverseOrder());

Kth largest element — heap of size K

Medium⭐ VIHeap▶ Visual▼

Maintain min-heap of size K — root is Kth largest after scanning. O(n log K) time.

Quickselect average O(n) — mention as follow-up.

Patterns: top K frequent (map + heap), merge K sorted lists, median from stream (two heaps).

Heap sort — how it works

MediumHeap▶ Visual▼
  1. Build max-heap from array — O(n)
  2. Swap root with end, heapify reduced size — n−1 times

O(n log n) time, O(1) extra space if in-place — unlike merge sort's O(n) aux.

Not stable. Java Arrays.sort uses dual-pivot quicksort for primitives, TimSort for objects.

LRU cache — HashMap + doubly linked list

Hard⭐ VIHeap▶ Visual▼

get/put O(1): map key→node; move node to head on access; evict tail when over capacity.

Real systems: Redis LRU, HTTP caches, DB buffer pool — ties DSA to system design.

Java shortcut (interview only if allowed)

LinkedHashMap with access-order=true + removeEldestEntry override.

7. Hashing

Hash tables/maps, collision handling, frequency counting.

4 questions in this section

How does a hash table work?

Medium⭐ VIHashing▶ Visual▼

hash(key) % bucketCount → index. Store (key, value) in bucket. Average O(1) get/put when load factor low.

Java HashMap

  • Default load factor 0.75 — resize/rehash when exceeded
  • JDK 8+: linked list → red-black tree when bucket > 8 nodes
  • Not thread-safe — ConcurrentHashMap for concurrency

Collision handling — chaining vs open addressing

MediumHashing▶ Visual▼
  • Chaining: bucket holds list/tree of entries — Java HashMap approach
  • Open addressing: probe next slot (linear, quadratic, double hashing) — used in some embedded DBs

Good hash function + load factor control keeps chains short.

Frequency counting — top K frequent elements

Easy⭐ VIHashing▶ Visual▼
  1. Count with HashMap — O(n)
  2. Min-heap of size K on counts, or bucket sort by frequency O(n)

Same pattern: anagram groups (sort string → key), first unique char, majority element (Boyer-Moore).

Group anagrams — hash map of signature

MediumHashing▶ Visual▼

Key = sorted string or char count array. O(n × k log k) with sort per word, O(n × k) with count key.

8. Graphs

Adjacency list/matrix, BFS, DFS, shortest path, MST, topological sort.

6 questions in this section

Graph representation — adjacency list vs matrix

Easy⭐ VIGraph▶ Visual▼
  • Adjacency list: Map<Integer, List<Integer>> — O(V+E) space, best for sparse graphs
  • Adjacency matrix: boolean[V][V] — O(V²) space, O(1) edge lookup
Map<Integer, List<Integer>> graph = new HashMap<>();
void addEdge(int u, int v) {
  graph.computeIfAbsent(u, k -> new ArrayList<>()).add(v);
}

BFS vs DFS on graphs

Medium⭐ VIGraph▶ Visual▼

BFS: queue, shortest path in unweighted graph, level-by-level. DFS: stack/recursion, detect cycle, connected components, topological sort.

Both O(V + E). Visited set prevents cycles.

void dfs(int node, Set<Integer> vis, Map<Integer, List<Integer>> g) {
  vis.add(node);
  for (int nei : g.getOrDefault(node, List.of()))
    if (!vis.contains(nei)) dfs(nei, vis, g);
}

Dijkstra's algorithm — shortest path (non-negative weights)

HardGraph▶ Visual▼

Min-heap of (distance, node). Relax neighbors if shorter path found. O((V+E) log V) with binary heap.

Bellman-Ford: handles negative edges, detects negative cycles — O(VE). Use when weights can be negative.

Minimum Spanning Tree — Kruskal vs Prim

HardGraph▶ Visual▼

Kruskal: sort edges by weight, Union-Find add edge if connects different components. O(E log E).

Prim: grow tree from start node with min-heap of frontier edges. O(E log V).

MST connects all vertices with minimum total edge weight — network design analogy.

Topological sort — course schedule / dependency order

Medium⭐ VIGraph▶ Visual▼

DAG only. Kahn's algorithm: BFS on nodes with indegree 0, reduce neighbor indegree. Or DFS postorder reverse.

Cycle detection: if processed nodes < V → cycle exists. Used for build pipelines, task schedulers.

Number of islands — grid DFS/BFS

Medium⭐ VIGraph▶ Visual▼

Scan grid; on '1' increment count and sink island (DFS flood fill). O(rows × cols).

Template for rotten oranges, word search, connected components in 2D.

Merge sort — divide and conquer

MediumSorting▶ Visual▼

Split array in half, sort halves, merge two sorted arrays. O(n log n) always, O(n) extra space.

Used in merge step of external sort, TimSort runs in Java 7+.

Quick sort — partition around pivot

MediumSorting▶ Visual▼

Pick pivot (last or random), partition so left ≤ pivot ≤ right, recurse. Average O(n log n), worst O(n²) on bad pivot — mitigated by random pivot.

In-place, cache-friendly — why Arrays.sort uses it for primitives.

Binary search (iterative)

Easy⭐ VISearch▶ Visual▼
public int binarySearch(int[] a, int target) {
  int lo = 0, hi = a.length - 1;
  while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] == target) return mid;
    if (a[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}

Follow-ups

First/last position of target — binary search then bias left or right. Search in rotated sorted array.

Merge intervals

MediumSorting▶ Visual▼

Sort by start; merge if overlap with last in result. O(n log n).

Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
List<int[]> res = new ArrayList<>();
for (int[] in : intervals) {
  if (res.isEmpty() || res.get(res.size() - 1)[1] < in[0]) res.add(in);
  else res.get(res.size() - 1)[1] = Math.max(res.get(res.size() - 1)[1], in[1]);
}

10. Dynamic Programming (DP)

Memoization vs tabulation, knapsack, LCS, Fibonacci, grid DP.

6 questions in this section

What is DP? Memoization vs tabulation

Medium⭐ VIDP▶ Visual▼

Optimal substructure + overlapping subproblems → cache results instead of recomputing.

  • Memoization (top-down): recursion + HashMap/array cache
  • Tabulation (bottom-up): fill table from base case up

Identify state: dp[i] or dp[i][j] meaning. Transition from smaller states.

Fibonacci — naive vs DP

EasyDP▶ Visual▼

Naive recursion O(2ⁿ). DP: dp[i]=dp[i-1]+dp[i-2], O(n) time O(1) space with two variables.

int a = 0, b = 1;
for (int i = 2; i <= n; i++) {
  int c = a + b;
  a = b;
  b = c;
}

Maximum subarray — Kadane's algorithm

Medium⭐ VIDP▶ Visual▼
int best = nums[0], curr = nums[0];
for (int i = 1; i < nums.length; i++) {
  curr = Math.max(nums[i], curr + nums[i]);
  best = Math.max(best, curr);
}
return best;

O(n) time O(1) space. dp[i] = max ending at i.

0/1 Knapsack problem

Medium⭐ VIDP▶ Visual▼

dp[w] = max value with capacity w. For each item, iterate w from W down to weight (avoid reuse).

int[] dp = new int[W + 1];
for (int i = 0; i < n; i++)
  for (int w = W; w >= weight[i]; w--)
    dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);

O(n × W) pseudo-polynomial. Subset sum is special case.

Longest Common Subsequence (LCS)

Medium⭐ VIDP▶ Visual▼
if (a[i] == b[j]) dp[i][j] = 1 + dp[i-1][j-1];
else dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);

O(m×n) time and space; roll array to O(n) space. Used in diff tools, DNA sequence alignment basics.

Related

Edit distance (Levenshtein) — insert/delete/replace costs.

DP on grids — unique paths & min path sum

MediumDP▶ Visual▼

Unique paths: dp[i][j] = dp[i-1][j] + dp[i][j-1]. Min path sum: dp[i][j] += min(top, left).

O(rows×cols) time; optimize to one row if only previous row needed.

11. Greedy Algorithms

Activity selection, fractional knapsack, Huffman coding — locally optimal → globally optimal (when provable).

4 questions in this section

Greedy vs DP — when to use greedy?

Medium⭐ VIGreedy▶ Visual▼

Greedy picks best local choice each step. Works when problem has greedy choice property and optimal substructure (often after sorting).

If greedy fails counterexample → use DP. Example: 0/1 knapsack needs DP; fractional knapsack allows greedy by value/weight ratio.

Activity selection — maximum non-overlapping intervals

Medium⭐ VIGreedy▶ Visual▼

Sort by end time. Take next activity that starts after last end. O(n log n).

Same pattern: meeting rooms (min heaps), non-overlapping arrows/balloons.

Fractional knapsack — greedy by value/weight ratio

MediumGreedy▶ Visual▼

Sort items by value/weight descending; take full item or fraction of next to fill capacity. O(n log n).

Contrast 0/1 knapsack — cannot take fractions, need DP.

Huffman coding — build optimal prefix codes

HardGreedy▶ Visual▼

Repeatedly merge two least frequent symbols into a tree (min-heap). Higher frequency → shorter bit code.

Used in compression (ZIP, JPEG stages). Greedy: always combine lowest two frequencies — proven optimal prefix code.
